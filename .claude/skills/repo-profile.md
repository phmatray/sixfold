## Integration style
- **Merge mode:** squash (linear `main`, every subject ends `(#PR)`; no branch protection or ruleset)
- **PR title convention:** Conventional Commits `<type>(scope): subject` — release-please cuts
  releases from them, so the squash title must have that form. Scopes in use: `engine`, `world`,
  `cards`, `web`, `ai`, `e2e`, `roadmap`. When an issue is closed, the title ends `(#issue)` and the
  squash appends `(#PR)`. A minor version is cut after every **3** merged `feat:`/`fix:` PRs

  Open every PR as a **draft** as soon as the branch has work.

## Conflict hot-spots (merge-with-main resolutions)
| File | Why it collides | Resolution |
|------|-----------------|------------|
| `Cargo.toml` `[workspace.package] version`, `.release-please-manifest.json` | release-please bumps them on release | take the **higher**; never bump by hand |
| `CHANGELOG.md` | release-please writes it | take **main's**; never hand-edit |
| `Cargo.lock` | dependency and crate churn (Renovate, new crates) | **regenerate** (`cargo check`) |
| `e2e/package-lock.json` | Renovate | **regenerate** (`npm install` in `e2e/`) |
| `.github/workflows/ci.yml` | several PRs add gates or reshape jobs | **union** the steps, then `actionlint` |
| `docs/ROADMAP.md`, `docs/*.md`, `README.md` | parallel features document themselves | **union** |
| `web/world/maps/*.json`, `web/world/quests.json` | map work lands in parallel | **union**, then `node tools/check-maps.mjs web/world --strict` |
| `web/src/world.rs`, `web/world/world.js` | the most-churned files | real code — understand both intents |
- **Rule of thumb:** union additive files, regenerate derived files, take-the-higher for the version;
  same-logic-both-sides is a real semantic conflict — understand both intents or stop.

## Architecture grain / invariants (shape implementation plans to these)
- One-way crates: `web -> meta -> engine`, `web -> engine`, `desktop -> web/dist`. `engine` never
  depends on `meta`.
- `engine/` (`sixfold-engine`) holds the duel: rules, card set, prebuilt decks, AI, tutorial. `meta/`
  (`sixfold-meta`) holds the game around it: campaign, world progress, shop, boosters, collection, deck
  lists, profile, stats, saves. Both are pure Rust with no `leptos`/`wasm-bindgen`/DOM.
- A rule you can assert with plain Rust goes in `engine` or `meta` with a unit test; a change that needs a
  browser to verify goes in `web` (Leptos) or `web/world/*.js` (three.js) with an e2e journey.
- The engine's `testkit` feature is for `sixfold-meta`'s tests only — never in the shipped build.
- Legal scope: only original rules, names and art. No Nintendo / Game Freak / The Pokémon Company assets,
  text or data; a reference `.gbc` ROM stays git-ignored and is never committed.
- `web/world/camera.js` imports nothing: node runs its tests and `tools/check-maps.mjs` reads it.

## Environment gotchas
- `cargo`/`rustc` missing from PATH → prepend `/opt/homebrew/opt/rustup/bin:$HOME/.cargo/bin`.
- A worktree-isolated session refuses compound shell commands that touch git (`cd … &&`, loops,
  `$(…)`): run git and `gh` as plain single commands, with `git -C <worktree>`.
- `guarded-commit.sh` passes its arguments to `git commit`, so stage untracked files first or use
  `-a`; a branch's first push needs `guarded-push.sh … <branch> -- -u origin <branch>`, and a branch
  made from `origin/main` must not track it (`switch --no-track -c`).
- e2e on CI runs on software GL (SwiftShader). `e2e/camera.spec.ts:141` expects that flat backdrop and
  fails on local macOS WebKit with a real GPU; the Playwright Linux image reproduces CI.
- `e2e/routines.spec.ts:10` is flaky on CI (#237); a red run on it alone is worth one re-run before
  debugging.
